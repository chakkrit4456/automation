# 15 — ขอคีย์ของแพลตฟอร์มโซเชียล (automation.itdev.in.th)

คู่มือนี้ใช้กับโดเมน `https://automation.itdev.in.th` ทำทีละแพลตฟอร์มได้เลย ไม่ต้องครบทั้งสี่ก่อนเริ่มใช้งาน แนะนำเริ่มจาก YouTube (ง่ายสุด) แล้วค่อย Meta และ TikTok

> หน้าตาของเว็บคอนโซลของแต่ละเจ้าเปลี่ยนบ่อย ชื่อเมนูอาจต่างจากที่เขียนไว้เล็กน้อย แต่ขั้นตอนหลักเหมือนเดิม

## ค่าที่ต้องใช้ซ้ำทุกแพลตฟอร์ม

| รายการ | ค่า |
| --- | --- |
| เว็บไซต์ / Homepage | `https://automation.itdev.in.th` |
| Privacy Policy URL | `https://automation.itdev.in.th/privacy` |
| Terms of Service URL | `https://automation.itdev.in.th/terms` |
| Data deletion URL | `https://automation.itdev.in.th/data-deletion` |
| อีเมลติดต่อ | อีเมลของคุณ (ใช้กรอกในฟอร์มทุกที่) |

สามหน้า `/privacy` `/terms` `/data-deletion` แอปสร้างไว้ให้แล้ว เปิดดูได้โดยไม่ต้องล็อกอิน แพลตฟอร์มจะตรวจว่าลิงก์เหล่านี้เปิดได้จริงตอนยื่นขออนุมัติ ดังนั้นต้อง **ติดตั้งและให้เว็บออนไลน์ก่อน** แล้วค่อยมาทำขั้นตอนข้างล่าง

**Redirect URI ที่ต้องลงทะเบียน** (ต้องตรงทุกตัวอักษร ไม่มี `/` ท้าย):

```text
https://automation.itdev.in.th/api/social/youtube/callback
https://automation.itdev.in.th/api/social/facebook/callback
https://automation.itdev.in.th/api/social/instagram/callback
https://automation.itdev.in.th/api/social/tiktok/callback
```

เมื่อได้คีย์แล้ว ใส่ใน `/opt/ai-social/.env` บนเซิร์ฟเวอร์ แล้วรัน `systemctl restart ai-social` (อย่าส่งคีย์ผ่านแชตหรือ commit ขึ้น GitHub)

## 1. YouTube (Google Cloud)

ได้ค่า: `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`

1. เข้า <https://console.cloud.google.com> ล็อกอินด้วยบัญชี Google ที่เป็นเจ้าของช่อง YouTube
2. สร้างโปรเจกต์ใหม่ (เช่น `ai-social-automation`)
3. ไปที่ **APIs & Services → Library** ค้นหา **YouTube Data API v3** กด **Enable**
4. ไปที่ **APIs & Services → OAuth consent screen** (หรือ Google Auth Platform)
   - User type: **External**
   - ใส่ชื่อแอป, อีเมลช่วยเหลือ, Homepage / Privacy Policy / Terms ตามตารางด้านบน
   - **Authorized domains:** `itdev.in.th`
   - เพิ่ม scope: `.../auth/youtube.upload` และ `.../auth/youtube.readonly`
   - เพิ่มอีเมลของคุณใน **Test users**
5. ไปที่ **Credentials → Create credentials → OAuth client ID**
   - Application type: **Web application**
   - **Authorized redirect URIs:** `https://automation.itdev.in.th/api/social/youtube/callback`
   - กดสร้าง จะได้ Client ID และ Client secret ใส่ลง `.env`
6. กลับไปหน้า OAuth consent screen กด **Publish app** (เปลี่ยนจาก Testing เป็น In production)
   เพราะถ้าค้างที่ Testing ตัว refresh token จะหมดอายุทุก 7 วัน ต้องเชื่อมบัญชีใหม่ทุกสัปดาห์ หน้าจะเตือนว่า "unverified app" ให้กด Advanced → Continue ได้ เพราะเป็นแอปของคุณเอง

**ข้อจำกัดที่ต้องรู้:** วิดีโอที่อัปโหลดผ่านโปรเจกต์ที่ยังไม่ผ่านการตรวจ (API compliance audit) จะถูกล็อกเป็น **private** วิธีแก้: ยื่นแบบฟอร์ม *YouTube API Services – Audit and Quota Extension Form* (ค้นชื่อนี้ใน Google ได้) ระบุว่าใช้อัปโหลดวิดีโอของตัวเองลงช่องตัวเอง ใช้เวลาประมาณ 1–4 สัปดาห์ (ระหว่างรอ คุณเปิดดูคลิป private แล้วกดเปลี่ยนเป็น public เองใน YouTube Studio ได้)
โควตาเริ่มต้น 10,000 หน่วย/วัน ≈ อัปโหลดได้ราว 6 คลิปต่อวัน

## 2. Facebook Page + Instagram (Meta for Developers)

ได้ค่า: `META_APP_ID`, `META_APP_SECRET` (และ `META_PAGE_ID` ถ้ามีหลายเพจ)

**เตรียมก่อน**
- Instagram ต้องเป็น **บัญชี Professional (Business หรือ Creator)** และ **ผูกกับ Facebook Page** ที่คุณเป็นแอดมิน (Instagram → ตั้งค่า → บัญชี → เปลี่ยนเป็นบัญชีมืออาชีพ → เชื่อม Page)
- ต้องมีบัญชี Facebook ที่เป็นแอดมินของ Page

**ขั้นตอน**
1. เข้า <https://developers.facebook.com> → **My Apps → Create App** (ลงทะเบียนเป็น Developer ถ้ายังไม่เคย)
2. เลือก use case ที่ครอบคลุมการจัดการเพจและเนื้อหา Instagram (ชนิดแอป **Business**) ตั้งชื่อแอป ใส่อีเมล
3. เพิ่มผลิตภัณฑ์ **Facebook Login for Business** (หรือ Facebook Login) แล้วที่ **Settings → Valid OAuth Redirect URIs** ใส่สองบรรทัด:
   - `https://automation.itdev.in.th/api/social/facebook/callback`
   - `https://automation.itdev.in.th/api/social/instagram/callback`
4. **App settings → Basic:** ใส่ Privacy Policy URL, Terms of Service URL, **App Domains** = `automation.itdev.in.th`, และ **User data deletion** = `https://automation.itdev.in.th/data-deletion` เลือกหมวดหมู่แอป
5. คัดลอก **App ID** และ **App Secret** (กด Show) ใส่ `.env`
6. ยังไม่ต้องสลับเป็น Live ก็ใช้ได้ (ดูด้านล่าง)

**โหมด Development vs Live**
- โหมด **Development:** บัญชีที่มี role ในแอป (Admin/Developer/Tester) โพสต์ลงเพจ/IG ที่ตัวเองดูแลได้ทันที โดยไม่ต้อง App Review นี่คือกรณีของคุณถ้าโพสต์ลงบัญชีตัวเอง ให้เริ่มด้วยวิธีนี้
- ต้อง **App Review + Business Verification** ก็ต่อเมื่อจะโพสต์ให้บัญชีของคนอื่น (ขอ Advanced Access ของ `pages_manage_posts`, `instagram_content_publish` ฯลฯ) ต้องยืนยันตัวตนธุรกิจและอัดวิดีโอสาธิต ใช้เวลาเป็นสัปดาห์

**ข้อควรระวัง:** สิทธิ์ที่แอปนี้ขอคือ `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`, `instagram_basic`, `instagram_content_publish`, `business_management` ตอนกด "เชื่อมต่อ" ต้องล็อกอินด้วยบัญชีที่มี role ในแอปและติ๊กเลือก Page ที่ต้องการ

## 3. TikTok (TikTok for Developers)

ได้ค่า: `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`

1. เข้า <https://developers.tiktok.com> ล็อกอินด้วยบัญชี TikTok แล้วสมัครเป็น Developer
2. **Manage apps → Connect an app** สร้างแอป ใส่ชื่อ, ไอคอน, คำอธิบาย, หมวดหมู่
3. กรอก URL ตามตาราง: Terms of Service, Privacy Policy และ Website
4. เพิ่มผลิตภัณฑ์ **Login Kit** แล้วใส่ Redirect URI: `https://automation.itdev.in.th/api/social/tiktok/callback`
5. เพิ่มผลิตภัณฑ์ **Content Posting API** และเปิด **Direct Post**
6. Scopes: `user.info.basic`, `video.publish`, `video.upload`
7. ถ้าพอร์ทัลให้ยืนยันโดเมน/URL prefix ให้ทำตามที่ขอ โดยมักเป็นการเพิ่ม **TXT record ใน Cloudflare DNS** ของ `itdev.in.th` (Cloudflare → DNS → Add record → Type TXT)
8. ตอนแอปยังอยู่ในโหมด Sandbox/Development ให้เพิ่มบัญชี TikTok ของคุณใน **Target users / Sandbox** ด้วย
9. คัดลอก **Client key** และ **Client secret** ใส่ `.env`

**ข้อจำกัดสำคัญ (ตามเอกสาร TikTok):** แอปที่ยังไม่ผ่านการตรวจ (audit) จะโพสต์ได้เฉพาะแบบ **ส่วนตัว (SELF_ONLY)** และ **เฉพาะบัญชี TikTok ที่ตั้งเป็น private** เท่านั้น ถ้าบัญชีเป็นสาธารณะ การโพสต์อาจถูกปฏิเสธ แอปจะถอยไปใช้ SELF_ONLY ให้อัตโนมัติเท่าที่ทำได้

**ยื่น audit เพื่อโพสต์สาธารณะ** (ใช้เวลาหลายสัปดาห์):
- อัดวิดีโอสาธิตให้เห็นครบ: ล็อกอิน/ยินยอม → หน้าเตรียมโพสต์ที่แสดงตัวเลือกความเป็นส่วนตัวของครีเอเตอร์ → ยืนยันก่อนโพสต์ → โพสต์ขึ้นจริง
- ขอเฉพาะ scope ที่ใช้ในวิดีโอสาธิตเท่านั้น
- ให้ลิงก์ Privacy / Terms เปิดได้จริง
- โพสต์ที่ลงตอนยังไม่ผ่าน audit จะยังเป็น private ตลอดไป ไม่ถูกเปลี่ยนย้อนหลัง

## ลำดับที่แนะนำ

1. ติดตั้งระบบบนเซิร์ฟเวอร์ให้ `https://automation.itdev.in.th` เปิดได้ (ดูหัวข้อ "ติดตั้งบนเซิร์ฟเวอร์จริง" ใน `docs/14-ขึ้นใช้งานจริง.md`)
2. YouTube → ใส่คีย์ → เชื่อมบัญชี → กด "ทดสอบ"
3. Meta (โหมด Development) → ใส่คีย์ → เชื่อมบัญชี → กด "ทดสอบ"
4. TikTok → ใส่คีย์ → เชื่อมบัญชี → ยื่น audit
5. ยื่น YouTube API audit ไปพร้อมกัน เพราะใช้เวลานาน
6. เมื่อทุกบัญชีทดสอบผ่าน ตั้ง `PUBLISHER_MODE=live` แล้วโพสต์ทดสอบทีละแพลตฟอร์ม

## แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุที่น่าจะเป็น |
| --- | --- |
| `redirect_uri_mismatch` | Redirect URI ในคอนโซลไม่ตรงกับ `PUBLIC_URL` ตัวอักษรต่อตัวอักษร (ตรวจ `https`, ไม่มี `/` ท้าย) |
| กด "เชื่อมต่อ" แล้วขึ้นว่าไม่มี credentials | ยังไม่ได้ใส่คีย์ใน `.env` หรือยังไม่ได้ `systemctl restart ai-social` |
| YouTube ต้องเชื่อมใหม่ทุก 7 วัน | OAuth consent screen ยังอยู่ในโหมด Testing ให้กด Publish app |
| YouTube คลิปเป็น private | ยังไม่ผ่าน API audit |
| Meta ไม่เห็น Page / IG | บัญชี IG ยังไม่เป็น Professional หรือยังไม่ผูก Page หรือบัญชีที่ล็อกอินไม่มี role ในแอป |
| TikTok โพสต์เป็นส่วนตัวเท่านั้น | แอปยังไม่ผ่าน audit (เป็นพฤติกรรมปกติ) |
